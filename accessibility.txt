=== Accessibility Statement ===
OceanWP is developed with accessibility in mind, continuously working toward full compliance with the WordPress Accessibility-Ready Theme requirements. To protect existing sites from unexpected layout changes, we have introduced a dedicated "Accessibility - A11Y" Customizer panel. For new installations, these native accessibility enhancements are enabled by default, while legacy installations can opt-in seamlessly to achieve an optimized, accessible experience.

For more information see: [WordPress Accessibility-Ready Guidelines](https://wpaccessibility.org/docs/topics/theme-guidelines/)

== Testing Tools and Methodology ==
Accessibility is integrated directly into the OceanWP core development, optimization, and update workflow. We utilize a hybrid approach combining automated evaluations and meticulous manual testing:

- **Automated Tools:** Internal structural audits and automated browser-based accessibility checkers to catch baseline contrast, labeling, and nesting flaws.
- **Keyboard Navigation:** Intensive manual testing to guarantee all interactive flows (such as toggle states and drop-downs) are entirely operable without a pointer device.
- **Screen Reader Text Handling:** Manual validation to ensure that utility styling explicitly outputs necessary non-visual hints for screen reader devices.
- **Regression Controls:** Reviewing all updates and user reports against our internal structural standards before any official theme release.

Primary accessibility testing tools include:
- [The WAVE browser extension](https://wave.webaim.org/extension/).
- Browser Inspectors for all major web browsers (Chrome, Opera, Firefox, Edge, Brave).
- Heading Mapping: Structural verification of logical heading trees and hierarchy containment using extensions.
- Zoom: Built-in browser zoom configurations, testing specifically up to 400% zoom (both regular page scaling and Text Only zoom layouts) to ensure preservation of content and functionality.

== Accessibility Features ==
*Note on Configuration:* To respect existing user designs, some advanced semantic HTML changes, stylesheets, and custom toggles are controlled via our Customizer panel. These options are enabled by default on all new site installations and remain fully configurable under user control.

- **Native A11Y Customizer Panel:** A dedicated suite of accessibility controls allowing administrators to globalize modern accessibility overrides.
- **Flexible Heading Architecture:** Theme layouts feature a naturally logical nested heading flow by default. To preserve ultimate layout authority for compliance and SEO requirements, users are given absolute control over heading tags via either the native WordPress Customizer settings or granular PHP filters.
- **Distinguishable Contextual Links:** In accordance with visual requirements, standard inline text links nestled inside main content bodies, post content, blocks, and widgets feature permanent underlines. State transitions are explicitly handled (eg., changes on mouse-over or focus states) without relying exclusively on color shifts.
- **Unambiguous Read More Contexts:** Standard blog index, archive, and query excerpt "Read More" or "Continue Reading" triggers are explicitly appended with screen-reader-accessible post title structures. This provides full utility context when screen reader users load individual elements out of context.
- **Accessibility-Safe Optimization Stylesheet:** A modular normalized stylesheet dedicated strictly to enforcing uniform accessibility patches, conditionally loaded only when core accessibility systems are active.
- **Semantic HTML Modernization:** Ongoing conversion of legacy element types into appropriate structural controls (eg., refactoring previous graphical links into semantic HTML `<button>` elements for search and mobile menu triggers, mobile menu toggles, and submenu/dropdown states).
- **Advanced Focus Trapping:** Enforced modal isolation and focus trapping for modern search forms and standard responsive menus, with built-in support for standard `Escape` key abandonment behavior.
- **Accessible Navigation Menus:** Navigation menus are built with proper list markup and include comprehensive support for keyboard-accessible dropdown menus.
- **External Link Icons:** Dedicated visual and screen-reader indicators for header and top bar social menus when links target external domains (configurable).
- **Form Field Accessibility:** Enhanced visual contextual labels natively positioned explicitly above form element inputs.
- **Media Header Controls:** Built-in semantic pause and play commands for standard video headers.
- **Skip to Content Link:** A visible-on-focus skip link is provided to allow keyboard users to bypass the navigation and jump directly to the main content area.
- **Keyboard Navigation & Focus Styles:** All interactive elements (menus, buttons, links, forms) are fully operable via keyboard with visible focus indicators.
- **ARIA Landmarks & Semantic Structure:** Core layout elements utilize HTML5 structural tags and appropriate ARIA landmark roles to establish a logical document outline for assistive technologies.
